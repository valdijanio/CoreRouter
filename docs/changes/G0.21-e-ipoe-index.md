history: G0.21: índice do IPoE segue a config por bloco (sobra da G4.3gb)

Config grande, parte e: o índice que o servidor DHCP usa para decidir o IPoE (`IpoeIndex`,
G4.3f) era refeito do zero a cada revisão da config, num laço sobre todos os `/ppp secret` e
todas as concessões fixas: 22 ms com 100 mil de cada a cada commit, dentro da rodada do DHCP e
com o lock do `Session`. Agora o nome do secret é procurado no índice que a própria lista já
mantém (`Secrets::first_named`, incremental desde a G4.3gb; anda a lista só numa config editada
à mão com um nome repetido e quando o primeiro não é IPoE), e as velocidades das concessões
fixas seguem a lista bloco a bloco (`CowList::shared_blocks`): uma revisão que mudou uma
concessão lê o bloco dela (128), não a lista. Duas concessões no mesmo endereço (só à mão)
fazem o índice ser refeito, e a última vale, como antes.

Como testar: `cargo test -p corerouter-engine --lib ipoe` (`refresh_equals_a_rebuild`: proptest,
o índice seguido é igual a um refeito do zero depois de qualquer série de escritas),
`cargo test -p corerouter-model --lib ppp_secrets`,
`cargo bench -p corerouter-engine --bench config_store -- ipoe_index`.

## perf

### G0.21 parte e — índice do IPoE (**medido**, AMD Ryzen AI Max+ 395, release, 2026-10-26)

`config_store/ipoe_index/*` (novo): o que a rodada do DHCP paga para seguir uma config com N
secrets IPoE e N concessões fixas com `rate_limit`, depois de um `ppp.secret.add`
(`secret_add`) ou da troca do `rate_limit` de uma concessão (`lease_set`). Antes =
`IpoeIndex::of` (refeito do zero); depois = `IpoeIndex::refresh`.

| Benchmark | Antes | Depois |
|---|---:|---:|
| `config_store/ipoe_index/secret_add/1000` | 104 µs | 22 ns |
| `config_store/ipoe_index/secret_add/10000` | 1,01 ms | 20 ns |
| `config_store/ipoe_index/secret_add/100000` | **22,5 ms** | **20 ns** |
| `config_store/ipoe_index/lease_set/1000` | 104 µs | 4,7 µs |
| `config_store/ipoe_index/lease_set/10000` | 995 µs | 9,2 µs |
| `config_store/ipoe_index/lease_set/100000` | **22,5 ms** | **35 µs** |

O que sobra no `lease_set` cresce com N/128: o `shared_blocks` monta um mapa dos blocos da
lista antiga (782 com 100 mil) para achar os que mudaram.
