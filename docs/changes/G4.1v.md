history: G4.1v feito (serve-stale com o prazo do cliente no encaminhador DNS)

DNS: o "client response timer" da RFC 8767 §5. Uma busca do encaminhador ainda fora 1,8 s depois
de começar responde com a entrada vencida, se o cache a tem dentro do `serve_stale_secs`, com TTL
30 s (§4). A resposta vai para o cliente que começou a busca e para todos os iguais que esperam ou
que chegam depois (G4.1o); a busca fica no mapa, então nenhuma outra sai para a origem, e segue
até o fim para renovar o cache (ou guardar a falha, RFC 9520). Sem entrada vencida, o cliente
continua esperando. Fica de fora: o caminho bloqueante (ferramentas do roteador, TCP 53 de
entrada e buscas com servidor cifrado, G4.1zk), que dá o vencido só quando todos falham.

Como testar: `cargo test -p corerouter-proto-dns lookup` (`stale_goes_out_early_and_the_lookup_goes_on`)
e `cargo test -p corerouter-daemon -- upstream::` (`a_dead_upstream_serves_stale_in_1_8_s`: a
origem cala depois de a resposta vencer; o cliente recebe o vencido entre 1,7 e 2,5 s, TTL 30).
No laboratório: `scripts/dns-stress-lab.sh --tests origin`.

No host (**medido**, `--userns`, release): vencido com as duas origens fora, 1ª vez: p50 2250 ms
(G4.1u) → 1800 ms; antes das três gaps, 4001 ms.
