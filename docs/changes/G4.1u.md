DNS: cada servidor de origem tem um RTO (RFC 6298: `SRTT + 4·RTTVAR`, α 1/8, β 1/4), entre 50 ms
e 120 s; nunca medido, 376 ms (Unbound). Uma busca pergunta os servidores em turno, cada consulta
esperando o RTO do servidor e a última o `query_server_timeout` inteiro; no máximo três envios
por servidor e três no total (RFC 9520 §3.1), ou um por servidor quando há mais de três. O
estouro dobra o RTO (§5.5) a partir do RTO daquela consulta (como o `rtt_lost` do Unbound), e a
consulta que estourou continua ouvindo: uma resposta atrasada dela vale. Um estouro só não marca
o servidor como fora: são três seguidos. `ip.dns.statistics.print` mostra o `rto_ms`.

Como testar: `cargo test -p corerouter-proto-dns lookup` (três tentativas com recuo, resposta
atrasada aceita, RTO vindo das medidas); no laboratório `scripts/dns-stress-lab.sh --tests origin`.
