history: G1.6zn criado (sistema na RAM no disco instalado; aviso claro quando o disco do sistema some)

Gap registrada a pedido do usuário depois do teste no notebook: com o sistema rodando de um
pendrive, tirar o pendrive com o roteador ligado enche o console de `SQUASHFS error` e `EXT4-fs
… I/O error`, porque o root é lido do disco sob demanda. A ISO live já copia o root para a RAM e
o confere (`apps/corerouter-init/src/live.rs`, G1.6y); falta o mesmo no disco instalado. Custo:
o `rootfs.squashfs` tem 87 MiB (**medido**, build G1.6zd); o boot fica 1–3 s mais lento num
pendrive (**estimado**). Quem faz assim: VMware ESXi, Alpine (modo "diskless" com `lbu commit`),
SmartOS, Cisco IOS clássico, `toram` dos live do Ubuntu/Debian.

| G1.6zn | Sistema na RAM no disco instalado | apps (init), sysupdate, engine, ui | Opção (ex.: `system.boot.to-ram`, desligada por padrão) que, no boot, copia o root do slot ativo para a RAM, confere pela mesma verity e roda de lá, reaproveitando o `live.rs`; sem RAM livre, segue do disco e avisa; o disco do sistema sumindo (pendrive tirado, SSD USB que reinicia) vira uma linha clara no console, no log e na saúde ("disco do sistema removido: a config não é mais gravada, reinicie") em vez de erros de I/O repetidos, e gravar config sem o disco falha com essa mensagem; teste no QEMU que tira o disco a quente (`device_del`) com o roteador continuando a responder | 1 d | aberto |
